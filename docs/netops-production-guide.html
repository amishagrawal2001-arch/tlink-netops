1. Overview

NetOps is a professional network topology design, simulation, and operations platform. It combines visual topology design with containerlab-based lab simulation, 3D WebGL visualization, digital twin monitoring, physical device mapping, and comprehensive automation — supporting 13 network vendors end-to-end.

🎨 Design

2D/3D topology canvas with drag-and-drop, 157 pre-built templates, vendor-specific config generation, IP addressing tools.

🚀 Simulate

One-click containerlab deployment, auto config push, inline terminal panels, cRPD/SONiC/Arista/Nokia container support.

🌐 3D View

Three.js WebGL 3D topology with orbit/zoom/pan, drag-to-move, drop-to-add, Shift+drag link creation, traffic particles.

🔮 Digital Twin

Real-time CPU/memory gauges, alarm pulse rings, config drift detection with diff viewer, per-node BGP status dashboard.

🔗 Device Mapping

LLDP/SNMP auto-discovery, CSV/JSON import, visual mapper wizard with auto-match scoring, persistent device inventory.

⚡ Automation

Event rules, workflow chains, scheduled jobs, compliance checks, change management, webhook notifications, backup history.

2. Quick Start Guide

Get started in 5 minutes. Install the app, load a template, deploy a lab, and start monitoring.

Step-by-Step

  1. Install the app — Download the installer for your platform (DMG, EXE, DEB, RPM, or AppImage) and install it. Make sure Docker and containerlab are installed on your system.
  2. Load a template — Open the app, click Templates in the toolbar, hover over any template to preview, and click to load it onto the canvas. Try "3-Stage IP Fabric (cRPD)" for a quick start.
  3. Deploy the lab — Click the Deploy button in the bottom bar. NetOps generates a containerlab YAML, launches containers, and pushes vendor configs automatically.
  4. Monitor with Twin — Click Twin in the view bar. CPU/memory gauges, BGP status, and alarm rings appear on each node. Click Dashboard for a tabular overview.
  5. Map to physical devices — Click Map in the bottom bar, upload a CSV/JSON of your real devices (or use LLDP discovery), and map them to topology nodes. Configs and monitoring extend to your physical network.

Workflow Diagram

1. Install App → 2. Load Template → 3. Deploy Lab → 4. Twin Monitor → 5. Map Devices
Design Topology → Generate Configs → Simulate in Lab → Validate BGP/LLDP → Export to Production
Tip: Right-click any node for quick access to terminals, config push, polling, and device properties.

4. Backend Server

Optional standalone server for large-scale deployments (100+ devices). Offloads SSH/SNMP polling from the desktop app to a centralized Linux server.

When to use: If you're polling 50+ devices, have multiple users, or need 24/7 monitoring with the app closed.

Deployment Options

Option 1: Direct Install (systemd)

# Copy tarball to server:
scp netops-server-1.0.0-linux.tar.gz root@server:~/

# On server:
tar xzf netops-server-1.0.0-linux.tar.gz
cd netops-server-1.0.0
./install.sh

# Management:
sudo systemctl status netops-server
sudo journalctl -u netops-server -f
sudo systemctl restart netops-server

Option 2: Docker

docker-compose up -d
# or for older Docker:
docker compose up -d

Option 3: Manual

cd server
npm install
npm start
# Listening on port 4000

Connect from App

  1. Open NetOps desktop app
  2. Automation menu → 🖥 Backend Server…
  3. Enter server URL: http://<server-ip>:4000
  4. Click Connect
  5. Green dot = connected — all SSH operations route through server

API Endpoints

MethodEndpointDescription
GET/api/statusServer health + connected client count
POST/api/pollPoll single device via SSH
POST/api/poll-allBatch poll (10 concurrent)
POST/api/backupFetch running config
POST/api/load-configPush config via interactive SSH shell
POST/api/discoverLLDP network discovery

WebSocket at ws://server:4000 streams poll results in real-time.

5. Configuration & Settings

Preferences File

Application preferences are stored in netops-prefs.json inside the platform-specific userData directory:

PlatformPath
macOS~/Library/Application Support/NetOps/netops-prefs.json
Windows%APPDATA%\NetOps\netops-prefs.json
Linux~/.config/NetOps/netops-prefs.json

File Types

ExtensionPurposeLocation
.topo.jsonTopology file — nodes, links, positions, configs, metadataUser-chosen save path
.inv.jsonInventory sidecar — device mappings, poll data, alarms, backupsSame directory as .topo.json, auto-derived name
netops-prefs.jsonApp preferences — recent files, backend server URL, window stateuserData directory

Settings Stored in Preferences

  • Backend server URL — persisted across sessions; auto-reconnects on app start
  • Theme — dark or light mode toggle (View menu or system preference)
  • Recent files — list of recently opened topology files
  • Window state — size and position of the app window
  • Device inventory — host, username, and vendor are saved per-device; passwords are NOT persisted

Inventory Sidecar Auto-Discovery

When opening a topology file (e.g., Lab.topo.json), the app looks for a sidecar inventory file in the same directory with these name patterns: Lab.inv.json, Lab.topo.inv.json, Lab-inv.json. If found, device mappings, poll data, and automation state are automatically restored.

17. Performance Tuning

SSH Connection Pool

ParameterValueDescription
Max per host3Maximum concurrent SSH connections to a single device
Max total50Global limit across all hosts
Idle timeout60 secondsConnections unused for 60s are automatically closed
Cleanup interval30 secondsIdle connection sweep runs every 30s

Polling Concurrency

ModeConcurrencyNotes
Local (desktop app)5 simultaneousPolls devices directly via local SSH pool
Backend server10 simultaneousPOST /api/poll-all batches to server SSH pool

Data Storage Limits

The automation engine enforces caps to prevent unbounded memory/storage growth:

Data TypeLimitBehavior
Active alarms200Oldest active alarms pruned beyond limit
Cleared alarms300Oldest cleared alarms pruned beyond limit
Config backups per node10Oldest backups rotated out when new backup is created
Event log entries500Oldest entries discarded (ring buffer style)

UI Performance Optimizations

  • Async parsing via setTimeout(0) — vendor output parsing yields to the event loop between parse calls, preventing UI thread blocking during large poll batches.
  • Viewport culling — for topologies with 80+ nodes, only visible elements are rendered in the DOM. Off-screen nodes are removed from the SVG to reduce paint cost.
  • Parallel link cache — O(1) lookup for parallel links between the same pair of nodes, avoiding O(n) scans during render.
  • WebSocket streaming — backend poll results arrive incrementally via WebSocket; the UI updates per-node as results arrive rather than waiting for all devices.

18. Security Considerations

Important: Review these considerations before deploying NetOps in a production environment.

Credential Handling

  • SSH credentials are stored in the topology JSON file and held in memory during operation. They are plaintext and not encrypted at rest.
  • Device inventory preferences save only host, username, and vendor per device. Passwords are never persisted in the inventory preferences file.
  • Credentials in .topo.json files may include SSH passwords for config push. Treat topology files as sensitive.

Backend Server Security

  • The backend server has no built-in authentication. Any client that can reach port 4000 can send SSH commands through the server.
  • Recommendation: Deploy the backend server behind a reverse proxy (nginx, Caddy, Traefik) with TLS and authentication.
  • Recommendation: Use VPN or SSH tunnel for remote access to the backend server.
  • Recommendation: Configure firewall rules to restrict access to port 4000 to trusted IP ranges only.

Content Security Policy

The Electron app sets a Content Security Policy (CSP) via a <meta> tag in index.html. The CSP allows ws: and wss: connections to any host (required for backend server connectivity to arbitrary IPs).

Recommended Production Hardening

MeasureDetails
Reverse proxyPlace nginx/Caddy in front of port 4000 with TLS termination and basic auth or OAuth
Firewallufw allow from 10.0.0.0/8 to any port 4000 — restrict to management subnet
VPNAccess backend server only via WireGuard/OpenVPN tunnel
File permissionsRestrict read access to .topo.json files: chmod 600 *.topo.json
Credential rotationRotate SSH credentials regularly; use SSH key-based auth where possible

19. Troubleshooting

Common Issues

App won't start

# Rebuild from source:
npm run build
npm start

# Check Electron version:
npx electron --version

Containerlab deploy fails with "CPU virtualization required"

Use cRPD mode (click OK when prompted) instead of full VM mode. cRPD works without KVM.

Backend server connection refused

# Check server status:
sudo systemctl status netops-server
sudo journalctl -u netops-server -f

# Check port:
curl http://server:4000/api/status

# Check firewall:
sudo ufw allow 4000/tcp

BGP shows 0/0 in live polling

JunOS truncates "Established" to "Establ" in BGP summary. This is handled by the parser. If still showing 0/0, restart the app to pick up the latest build.

Config push fails for cRPD

cRPD containers use enforce-startup-config: true in containerlab. The config push verifies instead of overwriting. Destroy and redeploy for config changes to take effect.

CSP blocks WebSocket connection

The CSP allows ws: and wss: connections to any host. If still blocked, check the Content-Security-Policy meta tag in index.html.

Apple metadata warnings in tar

Use gtar (GNU tar) instead of macOS tar when building server packages:

brew install gnu-tar
gtar czf package.tar.gz directory/

Topology file won't open / "inventory file" error

The app distinguishes between .topo.json (topology) and .inv.json (inventory sidecar) files. If you accidentally drag an inventory file, the app will show an error. Make sure you're opening the .topo.json file.

3D view shows blank canvas

WebGL must be supported by your GPU/driver. Check DevTools console for WebGL errors. On headless Linux or VMs without GPU passthrough, 3D view may not work. Switch back to 2D view.

Device polling returns empty results

  • Verify SSH credentials are correct for the target device.
  • Ensure the vendor is correctly set — wrong vendor means wrong command set.
  • Check if the device prompt is expected by the parser (some custom prompts break pattern matching).
  • Try polling a single device manually via right-click context menu to isolate the issue.

LLDP discovery finds no neighbors

  • LLDP discovery requires SSH access to the seed device.
  • LLDP must be enabled on the device interfaces.
  • The discovered neighbors must also be SSH-reachable for BFS traversal to continue.
  • SNMP discovery runs locally only — it does not route through the backend server.

Automation event rules not firing

  • Rules only evaluate during active polling. Make sure Digital Twin is active or scheduled polling is enabled.
  • Check the event log in the Automation Dashboard for suppressed or throttled events.
  • Webhook actions require the target URL to be reachable from the desktop app (or backend server if connected).

20. Known Limitations

  • SNMP discovery runs locally only — there are no backend API endpoints for SNMP operations. SNMP discovery always runs from the desktop app using the local net-snmp library.
  • cRPD EVPN overlay with eBGP underlay — requires local-as 65000 configuration on the underlay BGP sessions for eBGP fabrics. Without this, eBGP peering may fail.
  • 3D view annotation support — the Three.js 3D view does not render all 2D canvas annotations (text boxes, shapes, images). Switch to 2D view for full annotation support.
  • Container count limit — maximum of approximately 20 containerlab containers per lab, depending on Docker resource allocation (CPU, memory, disk). Large labs may require tuning Docker daemon settings.
  • WebSocket reconnect — if the backend server WebSocket connection drops, it does not automatically reconnect. You must disconnect and reconnect manually from the Automation menu.
  • Concurrent users — the backend server supports multiple WebSocket clients, but there is no conflict resolution if two users push configs to the same device simultaneously.
  • IPv6 polling — SSH polling to IPv6 management addresses works, but some vendor parsers may not handle IPv6 neighbor entries in LLDP output.
